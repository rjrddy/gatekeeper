# Project-specific interface: Release review dossier

Status: accepted for local implementation; publication pending approval.

## Context

The existing portfolio consoles shared a generic dashboard vocabulary. This made unrelated engineering problems look alike and hid the project’s primary object. The user explicitly authorized a visual redesign of the five kept projects.

## Decision

A steel-blue release dossier with a numbered section index, hard rules between evidence blocks and stamped policy verdicts. The public page reads as an inspection file, with findings arranged as rows rather than a metric-card grid.

Research reference: [GOV.UK task list guidance](https://design-system.service.gov.uk/components/task-list/). Task names and adjacent statuses should make completed and outstanding work easy to distinguish.

Pass/block verdicts remain responses from the verifier. The public cover says recorded evidence. The styling review verifies the existing signed scanner bundle and checks its actual blocking advisories. It does not claim that a new scanner campaign was run.

## Consequences

Maintain an independent visual vocabulary for this project; do not extract a shared cross-repository dashboard template. Preserve action names and API behavior so existing integration flows remain meaningful. Keep measured evidence and explicit hosting limits visible on the public page. Use system fonts and original code-native diagrams to keep the runtime self-contained. Save browser proof separately from the original benchmarks.
